# Setup, reproduction steps and differences from the paper

## 1. Environment

| Item | Value |
|---|---|
| Hardware | Kaggle notebook, GPU **T4 × 2** (16 GB each), Internet on |
| Python | 3.12 in an isolated `uv` venv at `/tmp/venv` (the Kaggle image ships 3.11) |
| LeRobot | `huggingface/lerobot` at commit **`ba83e4cf43737e2665be0aafcb5f513b83c7d0f3`**, installed with `uv pip install -e ".[smolvla,libero]"` |
| Simulator | LIBERO via LeRobot's `libero` extra, MuJoCo with EGL (headless) |
| Dataset (fine-tuning) | `lerobot/libero` at revision **`a1aaacb`** |
| Checkpoints | `lerobot/smolvla_libero` (paper config; paper-config checkpoint and CL base), `HuggingFaceVLA/smolvla_libero` (alternative checkpoint), `lerobot/smolvla_base` (fine-tuning cost test) |
| Seeds | evaluation seed 1000 everywhere (fixed LIBERO initial states); training seed 1000 (2000, 3000 for extra seeds) |

Every notebook installs this environment itself (≈ 10 min). The steps are:
1. Install the system packages `libegl1 libgl1 libglvnd0 libosmesa6 ffmpeg cmake build-essential`.
2. Create the `uv` Python 3.12 venv.
3. Clone LeRobot and check out the pinned commit.
4. Run `uv pip install --python /tmp/venv/bin/python -e ".[smolvla,libero]"`.
5. Import-check torch, lerobot, transformers, mujoco and libero.

## 2. Running the experiments

The notebooks are generated by `python kaggle/build_notebooks.py`, then pushed with `bash kaggle/kgl.sh push kaggle/<dir> 43200`. To run without Kaggle, use `scripts/` (see `README.md`). The helper fills your Kaggle username into `kernel-metadata.json`. Download outputs with `bash kaggle/kgl.sh output kaggle/<dir>`.

Kaggle allows at most **2 GPU batch sessions at a time** and 30 GPU-hours per week.

| Notebook | What it produces | Time on 2× T4 |
|---|---|---|
| `00_smoke_test` | install + 1-episode LIBERO eval | ~15 min |
| `01_r1_eval` | per-task success on LIBERO suites (`SUITES`, `POLICY`, `NAS` at the top); per-task timeout and retry | ~4.5 h for 3 suites |
| `02_r2_calibration` | paper-config checkpoint on Goal, action-chunk length test (n_action_steps 1/10/50), fine-tuning speed and memory | ~5 h |
| `03_cl` | short CL stage: SeqFT vs CIVD, 600 steps, old tasks 0/1/8 | ~2 h |
| `03_cl_run2` | main CL stage (**main result**): 1200 steps, all 9 old tasks | ~4.8 h |
| `03_cl_seed2`, `03_cl_seed3` | main stage with training seeds 2000 / 3000 | ~4.8 h each |
| `03_cl_ablation` | CIVD λ = 0.3 and CIVD w/o cross-instruction (distil with the *new* instruction) | ~5 h |
| `03_cl_er` | Replay-5 (5 demos per old task) and CIVD + Replay-1 (1 demo per old task) | ~4 h |
| `03_cl_lambda` | CIVD λ = 0.1 and λ = 0.03 | ~5 h |
| `03_cl_seed2_ext` | CIVD w/o cross-instruction and CIVD + Replay-1 with training seed 2000 | ~5 h |
| `03_cl_lambda01_seeds` | CIVD λ = 0.1 with training seeds 2000 and 3000 | ~5 h |
| `03_cl_er_controls` | Replay-1 without CIVD (control for CIVD + Replay-1) and Replay-5 with seed 2000 | ~3 h |

Each CL notebook works as follows:
1. **Smoke test.** A 3-step CIVD smoke run checks that the distillation loss is exactly 0 at step 1, where student = teacher.
2. **Training.** One method is trained per GPU in parallel. Settings: `--policy.train_expert_only=true`, batch 16, only the new task's demonstrations from `lerobot/libero`.
3. **Evaluation.** The new task is evaluated first, then the old tasks, with 10 episodes each.
4. **Summary.** It writes `cl/summary.md` with Wilson CIs, forgetting and new-task gain, plus time per step and memory.

### Running CIVD outside Kaggle

```bash
export CIVD_TEACHER=lerobot/smolvla_libero             # previous-stage model (frozen teacher)
export CIVD_OLD_TASKS="open the middle drawer of the cabinet|put the bowl on the stove|..."
export CIVD_LAMBDA=1.0 CIVD_DISTILL_BS=4 CIVD_MODE=old # CIVD_MODE=new gives the CIVD w/o cross-instruction ablation
python civd/civd.py --policy.path=lerobot/smolvla_libero --policy.train_expert_only=true \
  --dataset.repo_id=lerobot/libero --dataset.revision=a1aaacb "--dataset.episodes=[...]" \
  --rename_map='{"observation.images.image": "observation.images.camera1", "observation.images.image2": "observation.images.camera2"}' \
  --batch_size=16 --steps=1200 --seed=1000 --output_dir=outputs/civd
```

Every argument after `civd/civd.py` is passed to LeRobot's `lerobot_train` unchanged. The episode list for each LIBERO-Goal task is in `kaggle/libero_goal_episodes.json`.

## 3. Kaggle-specific fixes (needed to reproduce)

- **Use the venv's Python explicitly** (`/tmp/venv/bin/python -m lerobot.scripts.lerobot_eval`). Kaggle's own `/usr/local/bin/lerobot-*` scripts shadow the venv's.
- **EGL exposes only device 0** even with two GPUs. Render with `MUJOCO_EGL_DEVICE_ID=0` and place the policy on `cuda:$GPU`; otherwise the second GPU fails.
- **Set `MPLBACKEND=Agg`**, because the inline matplotlib backend breaks the subprocesses.
- **Answer the LIBERO first-import prompt for a dataset path with `N`.**
- **`lerobot/smolvla_libero` expects cameras `camera1`/`camera2`.** Pass the `--rename_map` shown above.
- **Build the task → episode map offline** from the per-frame `task_index` (`libero_goal_episodes.json`). Every instruction is asserted against LIBERO's task list at run time.

## 4. Differences from the paper (SmolVLA, Shukor et al. 2025)

| Item | Paper | This work | Expected effect |
|---|---|---|---|
| Checkpoint | authors' LIBERO model | `lerobot/smolvla_libero` (paper config); also `HuggingFaceVLA/smolvla_libero` (all VLM layers, 0.5× expert) | the HF checkpoint is a different model (76 % vs 88 %) |
| n_action_steps | not stated for LIBERO | 10 (paper-config checkpoint), 1 (alternative checkpoint default), 1/10/50 (action-chunk length test) | up to −60 pp at 50 |
| Suites | 4 | all 4 for paper-config checkpoint (83.3 % vs 87.3 %) | Spatial/Object 8–9 pp lower |
| Episodes | not stated | 10 per task, seed 1000 | Wilson CI ≈ ±6–7 pp per suite |
| Images | — | rendered 360², data 256², both padded to 512² | small train/eval shift |
| Precision / GPU | A100-class | bf16 weights on T4 (no native bf16) | slower (9.4 s/step at batch 32), not less accurate |

## 5. Known limitations

- **One CL stage only.** The full 5-stage protocol is the evaluation plan in the report (§5.5).
- **10 episodes per task**, so a single task's success rate carries a wide CI. I therefore report pooled tests across tasks.
- **CIVD needs old tasks to share the observation space of the new data.** This holds in LIBERO-Goal but not across scenes.
